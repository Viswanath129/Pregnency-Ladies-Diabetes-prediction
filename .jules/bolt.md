## 2024-05-18 - [FastAPI CPU-bound Endpoint Optimization]
**Learning:** For FastAPI endpoints that execute CPU-bound operations (like single-row scikit-learn model inferences), using `async def` blocks the main thread and severely degrades performance under concurrent load. Furthermore, creating `pandas.DataFrame` objects for single-row inference adds significant overhead compared to using raw `numpy.array`. Numpy scalar operations like `np.clip` or `np.std` also have high overhead on very small arrays and should be replaced with pure Python math functions where appropriate.
**Action:** When implementing machine learning inference in FastAPI, always use standard `def` (so FastAPI runs the request in an external thread pool), pass 2D `numpy.array` instead of DataFrames for prediction, and replace numpy scalar functions with pure Python equivalents for small inputs. Avoid using `catch_warnings` in threaded endpoints and prefer global `warnings.filterwarnings`.
