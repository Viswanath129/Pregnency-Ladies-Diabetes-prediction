## 2024-06-07 - Python Object Creation Overhead in Fast API Loops
**Learning:** Using `pandas.DataFrame` and certain numpy operations (like `np.std`, `np.clip`, `np.random.normal`) for single-row/scalar data introduces significant overhead in FastAPI routes due to high object creation and validation costs. Our benchmark showed a ~34x speedup when bypassing pandas for inference and using standard python `math`/`random` modules for scalar operations. Additionally, FastAPI's `async def` on CPU-bound operations (like sklearn inference) blocks the event loop, further reducing throughput.
**Action:** When handling single row API requests, use standard python types, `math`, or 2D `numpy.array` without `pandas`. For computationally heavy ML endpoints, define them using standard `def` instead of `async def` so FastAPI runs them in its external threadpool. Wrap scikit-learn numpy inferences with `warnings.catch_warnings()` to suppress missing feature names warnings.
