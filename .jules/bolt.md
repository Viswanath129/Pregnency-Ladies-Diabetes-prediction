## 2024-05-24 - [FastAPI & ML Inference Performance]
**Learning:** For single-row ML inferences in a FastAPI application, using pandas DataFrames and NumPy array operations for scalar values introduces massive overhead (e.g., 0.6ms vs 0.01ms per request). Additionally, using `async def` for endpoints that perform synchronous, CPU-bound ML inferences blocks the asyncio event loop.
**Action:** Always use standard `def` for FastAPI endpoints doing CPU-bound work (allowing FastAPI to run them in an external thread pool). For single-row model predictions, use 2D `numpy.array` instead of `pandas.DataFrame` and suppress the resulting `UserWarning` regarding feature names. Replace scalar NumPy operations (like `np.std`, `np.clip`, `np.random.normal`) with pure Python equivalents (`math`, `min`/`max`, `random.gauss`) to avoid overhead.
