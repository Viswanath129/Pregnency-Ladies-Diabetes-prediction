## 2024-05-15 - [FastAPI Thread Pooling vs Pandas DataFrame Overhead]
**Learning:** For CPU-bound workloads like scikit-learn model inference in FastAPI, changing `async def` to `def` allows FastAPI to use an external thread pool, which is generally better. However, when using Pandas `DataFrame` instantiation, thread pooling causes significant lock contention or overhead that *decreases* performance by ~60%. By replacing `pd.DataFrame` with `numpy.array` *first*, the inference speed improves significantly. Bypassing Pandas is critical before relying on thread pooling for single-row inference.
**Action:** When optimizing CPU-bound endpoints in FastAPI, prioritize removing high-overhead object creations (like `pd.DataFrame` for single rows) before changing concurrency models, as thread pool overhead can eclipse minor synchronous performance gains.
