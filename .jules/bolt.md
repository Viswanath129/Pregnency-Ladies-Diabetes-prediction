## 2024-06-23 - FastAPI Concurrency and NumPy Overhead
**Learning:** In a FastAPI app handling CPU-bound scikit-learn inferences, defining endpoints with `async def` severely degrades performance because the synchronous ML predictions block the main event loop. Furthermore, using NumPy operations (like `np.clip`, `np.std`, `np.random.normal`) on scalar values adds immense overhead compared to pure Python equivalents (`min`/`max`, `math.sqrt`, `random.gauss`), taking ~40x longer. Bypassing Pandas DataFrames for single-row inference via a raw 2D NumPy array also significantly lowers overhead.
**Action:** Always use standard `def` for CPU-bound ML inference routes in FastAPI to utilize thread pooling. Replace NumPy scalar calculations with standard Python math for micro-optimizations, and bypass Pandas when only inferencing on a single row.
