## 2024-06-25 - FastAPI ML Inference Threading and Numpy Overhead
**Learning:** In FastAPI, using `async def` for a CPU-bound endpoint (like Scikit-Learn inference) severely bottlenecks throughput because it runs synchronously on the main event loop. Furthermore, instantiating `pandas.DataFrame` or calling NumPy scalar functions (like `np.random.normal`, `np.clip`, `np.std`) inside these fast endpoint loops introduces massive per-request lock contention and object overhead.
**Action:** Always declare CPU-bound ML endpoints as `def` so FastAPI delegates them to a thread pool. When optimizing these single-request paths, bypass pandas entirely by feeding 2D `np.array` into `model.transform`/`model.predict`, and replace NumPy scalar operations with native Python equivalents (`random.gauss`, `min`/`max`, `math.sqrt`) to maximize ops/second.
