## 2024-05-14 - [FastAPI + Scikit-Learn Overhead]
**Learning:** In fast API loops, avoid using `pandas.DataFrame` instantiation for single-row scikit-learn model inferences, as it adds massive overhead (~2.5ms per request). Similarly, using NumPy functions (like `np.std`, `np.clip`, or `np.random.normal`) for scalar values or very small arrays introduces significant overhead compared to pure Python equivalents. Also, CPU-bound endpoints (like ML inference) should be defined as `def` rather than `async def` to prevent blocking the main event loop.
**Action:** Always bypass `pandas.DataFrame` and use 2D `numpy.array` wrapped in `warnings.catch_warnings()` for single-row inference. Replace small NumPy array operations with pure Python equivalents (e.g., manual variance, `min`/`max`, `random.gauss`). Use standard `def` for FastAPI handlers doing CPU-bound work.
