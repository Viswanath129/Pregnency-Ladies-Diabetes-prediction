
## 2024-06-02 - [Backend Prediction Endpoint Performance Boost]
**Learning:** Found that the /predict route was suffering from multiple overheads when handling fast, single-row API calls. These included `async def` handling CPU-bound scikit-learn models (blocking the main event loop), using `pd.DataFrame` for one row of inputs which takes a heavy toll compared to plain `np.array`, and using heavy `numpy` array manipulation and statistics logic (`np.random.normal`, `np.clip`, `np.std`) for very tiny arrays or scalar values which is noticeably slower than standard built-in pure Python operations like `random.gauss`, `min`, `max`, and mathematical variance algorithms.
**Action:** Always make sure `def` instead of `async def` is used for routes with CPU-intensive operations to make use of FastAPI's background threadpool. When transforming single API payload rows for scikit-learn models, directly bypass Pandas by using `np.array` and suppressing explicit warnings. For purely mathematical or scalar distributions on a tiny dataset size, always replace NumPy logic with `math` or pure Python equivalents.
